# SoftMix E-Commerce Platform

Полнофункциональная e-commerce платформа на базе микросервисной архитектуры с использованием Nx monorepo.

<a alt="Nx logo" href="https://nx.dev" target="_blank" rel="noreferrer"><img src="https://raw.githubusercontent.com/nrwl/nx/master/images/nx-logo.png" width="45"></a>

✨ **This workspace has been generated by [Nx, a Smart, fast and extensible build system.](https://nx.dev)** ✨

## Описание

SoftMix — это современная платформа электронной коммерции, построенная с использованием:
- **Frontend**: React 18 + Redux Toolkit + TypeScript
- **Backend**: NestJS + TypeScript (микросервисная архитектура)
- **Базы данных**: MongoDB (пользователи) + PostgreSQL (товары)
- **Контейнеризация**: Docker + Docker Compose

## Требования

- **Node.js**: 18.x или выше
- **npm**: 9.x или выше
- **Docker**: 20.x или выше
- **Docker Compose**: 2.x или выше

## Архитектура

Проект состоит из 5 микросервисов:

```
┌─────────────┐
│   Frontend  │ (React, порт 4200)
│  (клиент)   │
└──────┬──────┘
       │
       ↓
┌─────────────┐
│     BFF     │ (API Gateway, порт 5555)
│  (Backend   │
│   For       │
│  Frontend)  │
└──────┬──────┘
       │
       ├─────────→ ┌──────────────┐
       │           │    Users     │ (Аутентификация, порт 3333)
       │           │   Service    │ → MongoDB
       │           └──────────────┘
       │
       ├─────────→ ┌──────────────┐
       │           │     Shop     │ (Каталог товаров, порт 4444)
       │           │   Service    │ → PostgreSQL
       │           └──────────────┘
       │
       └─────────→ ┌──────────────┐
                   │   Uploader   │ (Загрузка файлов, порт 7777)
                   │   Service    │ → MongoDB + File Storage
                   └──────────────┘
```

### Микросервисы

| Сервис | Порт | Технологии | Назначение |
|--------|------|------------|------------|
| **Frontend** | 4200 | React 18, Redux Toolkit | Пользовательский интерфейс |
| **BFF** | 5555 | NestJS | API Gateway, агрегация запросов |
| **Users** | 3333 | NestJS, MongoDB, JWT | Аутентификация и управление пользователями |
| **Shop** | 4444 | NestJS, PostgreSQL | Каталог товаров и категорий |
| **Uploader** | 7777 | NestJS, MongoDB, Multer | Загрузка и управление файлами |

### Shared Libraries

- **@project-lib/core** - базовые утилиты NestJS (middleware, decorators, exceptions, guards)
- **@project-lib/shared-types** - общие TypeScript интерфейсы

## Установка

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd softmix-workspace/softmix
```

### 2. Установка зависимостей

```bash
npm install
```

### 3. Настройка environment переменных

**Автоматически (рекомендуется):**

Запустите `npm start` и скрипт автоматически создаст `.env` файлы из примеров.

**Вручную:**

```bash
cd environments

# Для Users сервиса
cp .users.env.example .users.env

# Для Shop сервиса
cp .shop.env.example .shop.env

# Для Uploader сервиса
cp .uploader.env.example .uploader.env

# Для BFF сервиса
cp .bff.env.example .bff.env
```

> **Примечание:** Все `.env` файлы находятся в папке `environments/` и автоматически подключаются в docker-compose.yml

**ВАЖНО**: Измените секреты в production файлах!

Обязательно обновите:
- `JWT_ACCESS_SECRET` - секретный ключ для access токенов
- `JWT_REFRESH_SECRET` - секретный ключ для refresh токенов
- `MONGO_PASSWORD` - пароль для MongoDB
- `POSTGRES_PASSWORD` - пароль для PostgreSQL
- `ALLOWED_ORIGINS` - список разрешенных доменов для CORS

## Запуск

### Development режим

#### Вариант 1: Интерактивный запуск (рекомендуется) ⭐

```bash
npm start
```

Интерактивное меню позволит выбрать нужный режим запуска.

#### Вариант 2: Docker Compose

```bash
npm run docker:up
```

или

```bash
docker-compose up
```

Сервисы будут доступны по адресам:
- Frontend: http://localhost:4200
- BFF API: http://localhost:5555
- Users API: http://localhost:3333
- Shop API: http://localhost:4444
- Uploader API: http://localhost:7777

**Полезные команды для Docker:**

```bash
# Просмотр логов всех сервисов
npm run docker:logs

# Остановка всех контейнеров
npm run docker:down

# Пересборка и запуск
npm run docker:rebuild
```

#### Вариант 3: Локальный запуск для разработки

**Все сервисы сразу:**

```bash
npm run start:dev
```

**Только backend сервисы (без frontend):**

```bash
npm run start:backend
```

**Только микросервисы (Users, Shop, Uploader):**

```bash
npm run start:services
```

**Запуск отдельных сервисов:**

```bash
# Frontend
nx serve frontend

# Users service
nx serve users

# Shop service
nx serve shop

# Uploader service
nx serve uploader

# BFF service
nx serve bff
```

## API Документация

### Swagger документация

После запуска сервисов Swagger документация доступна по адресам:

- Users API: http://localhost:3333/spec
- Shop API: http://localhost:4444/spec
- Uploader API: http://localhost:7777/spec
- BFF API: http://localhost:5555/spec

### Основные эндпоинты BFF

#### Аутентификация

```
POST   /api/auth/login              # Вход в систему
POST   /api/auth/logout             # Выход из системы
GET    /api/auth/refresh            # Обновление токена
```

#### Пользователи

```
GET    /api/users                   # Получить всех пользователей
GET    /api/users/:id               # Получить пользователя по ID
GET    /api/users/verify            # Проверить токен
POST   /api/users                   # Создать пользователя
PATCH  /api/users/:id               # Обновить пользователя
DELETE /api/users/:id               # Удалить пользователя
```

#### Товары

```
GET    /api/products                # Получить список товаров
GET    /api/products/:id            # Получить товар по ID
POST   /api/products                # Создать товар
PATCH  /api/products/:id            # Обновить товар
DELETE /api/products/:id            # Удалить товар
```

#### Категории

```
GET    /api/categories              # Получить все категории
GET    /api/categories/:id          # Получить категорию по ID
POST   /api/categories              # Создать категорию
PATCH  /api/categories/:id          # Обновить категорию
```

## Безопасность

Проект использует следующие меры безопасности:

- ✅ JWT аутентификация (access + refresh tokens)
- ✅ Bcrypt хеширование паролей (SALT_ROUNDS = 10)
- ✅ CORS с whitelist разрешенных origins
- ✅ Параметризованные запросы (защита от SQL/NoSQL injection)
- ✅ Валидация входных данных через class-validator
- ⏳ HttpOnly cookies для refresh токенов (рекомендуется)
- ⏳ Rate limiting (рекомендуется добавить)
- ⏳ Helmet для security headers (рекомендуется добавить)
